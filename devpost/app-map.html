wovain app map

wovain is a hosted MCP server for print-on-demand sellers. Any agent that speaks MCP with OAuth, such as ChatGPT or Claude, connects to it remotely. Inside one chat it turns an idea into a live Fourthwall product, makes video ads for it, and builds one Meta Advantage+ sales campaign guarded by five automated rules.

One action, end to end: “Add to campaign”

What happens between pressing Add to campaign on the ad widget and seeing the campaign widget with its rules.

  1. Ad widget button records the choice, then posts a chat message.
    apps/widgets/src/ad/ad-widget.tsx · onAdd → tool record_ad
  2. Request reaches /mcp with the merchant's OAuth token, which is checked before any tool runs.
    apps/server/src/app.ts → apps/server/src/routes/mcp.ts
  3. Ads playbook tells the agent that once no ad widgets are waiting, it starts the campaign step.
    apps/server/src/playbooks/ads.ts → apps/server/src/playbooks/campaign.ts
  4. Plan: budget in cents, ad names, product links with UTM tags.
    apps/server/src/tools/campaign.ts · campaign_plan
  5. Meta Ads connector builds the draft campaign, ad set and video ads.
    The agent's Meta Ads connector (outside this repo)
  6. Rules: five payloads in cents, posted to Meta's rules API.
    apps/server/src/tools/campaign.ts · create_rules → packages/shared/src/rules.ts · metaRules → apps/server/src/lib/meta-graph.ts
  7. Campaign widget shows Ready, Live or blocked, with each rule's threshold.
    apps/widgets/src/campaign/campaign-widget-view.tsx

Reference route: three stops

A reference route through the code above; it wasn't toured together.

1. The button · apps/widgets/src/ad/ad-widget.tsx, search onAdd

The widget calls the server tool record_ad directly so the choice is saved even if the chat moves on, then sends “Added the ads for design d1 to the campaign” so the agent continues with the playbook.

2. The rules tool · apps/server/src/tools/campaign.ts, search "create_rules"

Reads the added ads and each product's breakeven from the store, builds the five rules, skips any that already exist in Meta, and records which ones are in place. Without a Meta token it creates nothing and returns the fix instead.

3. The thresholds · packages/shared/src/rules.ts, search metaRules

Turns breakeven × your Settings multiples into Meta filters in cents: for example 3 × breakeven spend with no sales pauses an ad. The test apps/server/test/campaign-tools.test.ts pins the PRD demo tee's numbers ($30.96 kill, $8.26 scale).

A practice to reuse

Keep money math out of the model, and pin it with a test. The playbooks pass copy and choices; prices, breakeven and rule thresholds are computed by the server from stored data (packages/shared/src/ad.ts says so at the top), and campaign-tools.test.ts checks the exact cents Meta receives. When the first live run sent the rules to Meta, the thresholds matched without a fix. On any agent-built app that moves money, compute the numbers in code the model calls, and write one test with a worked example from the spec.

Run it again

  • bun install, then copy apps/server/.env.example to apps/server/.env and fill in the keys you need.
  • In ChatGPT (developer mode) or Claude, add https://wovain.vercel.app/mcp as a remote MCP server, then sign in with Google and approve access when the agent asks.
  • Locally: bun run db:migrate once, then bun run dev (serves /mcp on localhost:3000) plus bun run widgets:watch, and connect the agent to https://<tunnel>/mcp.
  • See every widget without an agent: bun run storybook.
  • Checks: bun run check, bun run typecheck, bun test, bun run test:stories.

Paths and names can drift as the code changes.
