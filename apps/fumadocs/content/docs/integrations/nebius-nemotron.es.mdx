---
title: Nebius y Nemotron
description: Cómo usa wovain NVIDIA Nemotron en Nebius Token Factory como juez y tomador de decisiones del autopilot.
---

Wovain llama a **NVIDIA Nemotron 3 Super** (`nvidia/nemotron-3-super-120b-a12b`) en **Nebius Token Factory**. El endpoint es compatible con OpenAI: `https://api.tokenfactory.nebius.com/v1/`, autenticado con `NEBIUS_API_KEY`.

Nemotron hace dos trabajos. Nunca sustituye los límites que impone el código.

## 1. Juez de diseño

Antes de mostrar un diseño para su aprobación, Nemotron recibe el brief del diseño: idea, modelo, ubicación, colores, metadatos de la ilustración, ficha del producto y una descripción opcional de la ilustración. Devuelve un juicio validado con Zod:

- un veredicto, `ready` o `revise`
- una puntuación de 0 a 100
- una comprobación superada o fallida por cada regla de impresión, con una nota breve
- hasta cinco correcciones y una frase de coaching sugerida

Las reglas que el código puede decidir (tamaño de impresión, transparencia, longitud del título, número de colores) las calcula el código y prevalecen sobre el modelo. Si alguna falla, el veredicto es `revise` diga lo que diga Nemotron. Una respuesta que no se puede analizar, o un error de Token Factory, se convierte en un mensaje seguro para el usuario y el diseño se muestra sin la comprobación.

## 2. Decisiones del autopilot

En autopilot, cada punto de aprobación es una decisión de Nemotron: qué idea seguir, la ficha y el precio, si el diseño evaluado es suficientemente bueno, los conceptos de anuncio y el presupuesto de la campaña. Cada respuesta se valida con un esquema y después el código aplica los límites estrictos:

| Límite | Lo aplica el código |
| --- | --- |
| Precio | No por debajo del punto de equilibrio del modelo más el margen mínimo |
| Presupuesto diario | No por encima del presupuesto solicitado ni del máximo de los ajustes |
| Revisión de marcas | Una coincidencia con la frase del título o las palabras del arte descarta la idea |
| Juez | Debe alcanzar `ready` en un máximo de revisiones |
| Coste de la ejecución | Un paso que superaría el gasto máximo no se inicia |
| Activación | Ningún procedimiento activa un objeto de Meta; las campañas siguen en pausa |

Cada decisión se guarda con sus entradas, opciones, la elección, el razonamiento de Nemotron, los límites que se aplicaron y si el código corrigió al modelo, para que el vendedor pueda auditar una ejecución.

## Por qué Nemotron

- Un segundo modelo con una rúbrica fija y un esquema detecta lo que la autorrevisión del agente anfitrión pasa por alto.
- La salida estructurada y el razonamiento tipo herramienta a bajo coste por llamada encajan con muchas decisiones pequeñas por ejecución.
- Ejecutar las decisiones en Token Factory las hace independientes de que el agente anfitrión siga en el bucle, lo que importa en ejecuciones largas de autopilot.

## Configuración

```bash
NEBIUS_API_KEY=...
```

Sin la clave, el juez responde `configured: false` y el autopilot no está disponible. Nada más se rompe.
