## Prérequis

- Node.js (voir `.nvmrc`) et pnpm
- Docker, pour le PostgreSQL local (`docker-compose.yml`)

## Lancer le projet

```bash
pnpm install
docker compose up -d      # local PostgreSQL
pnpm run dev              # web app and docs through Turborepo
```

| Application     | Chemin          | Port                         |
| --------------- | --------------- | ---------------------------- |
| Application web | `apps/web`      | Par défaut de Next.js (3000) |
| Documentation   | `apps/fumadocs` | 4000                         |

## Variables d'environnement avec Varlock

Chaque application possède son fichier `.env.schema`. [Varlock](https://varlock.dev) valide les valeurs au démarrage et génère un `src/env.ts` typé : le code importe donc `ENV` au lieu de lire `process.env`.

L'application web a besoin de :

| Variable | Signification |
| --- | --- |
| `NODE_ENV` | `development`, `production` ou `test` |
| `BETTER_AUTH_SECRET` | Au moins 32 caractères ; signe les sessions |
| `BETTER_AUTH_URL` | URL publique de l'application web |
| `DATABASE_URL` | Chaîne de connexion PostgreSQL (Cloud SQL en production) |

L'application de documentation a une clé optionnelle, `NEBIUS_API_KEY` (Nemotron sur Nebius Token Factory ; `DOCS_CHAT_MODEL` et `NEBIUS_BASE_URL` ont des valeurs par défaut), pour le chat IA. Sans la clé, le point d'accès du chat répond 503.

Les clés des fournisseurs (Nebius, Qloo, Tavily, fal) sont décrites sur chaque [page d'intégration](/fr/docs/integrations).

## Base de données

Drizzle gère le schéma dans `packages/db`. Générez les migrations avec `pnpm run db:generate`. Les tables d'authentification sont générées avec `pnpm run auth:generate` ; ne les modifiez pas à la main.

## Avant de commiter

```bash
pnpm run check         # Ultracite: Oxlint and Oxfmt
pnpm run check-types
pnpm run knip
```
