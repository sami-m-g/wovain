wovain app map

An agentic print-on-demand app: Qloo finds who would buy, Tavily finds why now, Nemotron judges the designs, and the seller approves Fourthwall products and a paused Meta campaign.

Snapshot of source commit bec50f3 on the rebuild branch. Code drifts; the repository is the source of truth. Live: wovain.com, docs: docs.wovain.com.

The pieces

One Next.js 16 app (apps/web) serves the website, the API and the ChatGPT MCP server on Cloud Run. The API is a set of oRPC procedures (packages/api), sign-in is Better Auth (packages/auth) and data lives in PostgreSQL through Drizzle (packages/db). The docs are a separate Fumadocs site (apps/fumadocs) in English, French and Spanish.

One action, from click to result

Today the router has a health check and a private-data procedure; the seller-flow procedures (trends, designs, judge, approve, products, ads, campaign) are the planned next slices.

Reference route (3 stops)

A reference route, not a toured one. Search for the symbol if line numbers have moved.

Stop File Anchor What happens
1 apps/web/src/app/api/rpc/[[...rest]]/route.ts handleRequest Identifies the user, builds the context and hands the request to oRPC.
2 packages/api/src/routers/index.ts appRouter Lists the procedures the website and ChatGPT can call.
3 packages/api/src/index.ts protectedProcedure Adds evlog logging, then rejects requests without a session.

To change this, start here

Add or change a procedure

Edit packages/api/src/routers/index.ts (appRouter). Use protectedProcedure for anything that needs a signed-in seller.

Change sign-in

packages/auth/src/index.ts (createAuth); the route is apps/web/src/app/api/auth/[...all]/route.ts. Never edit packages/db/src/schema/auth.ts by hand; run pnpm run auth:generate.

Change the database

Schema and relations are in packages/db/src; generate a migration with pnpm run db:generate.

Change the docs or translations

Pages are in apps/fumadocs/content/docs with .fr.mdx and .es.mdx siblings; locales are set in apps/fumadocs/src/lib/i18n.ts. The planning documents are docs/scope.md, docs/prd.md and docs/spec.md.

A practice to reuse

Write the limit as an observable rule before building the feature. In this project, docs/prd.md says a price is never below the blank's breakeven, and docs/spec.md says code-decided checks overwrite the model's answer. That turns "the model should not underprice" into a test you can run, and the same habit works on any project that lets a model make decisions.

Run it again

pnpm install, docker compose up -d, then pnpm run dev. Before committing: pnpm run check, pnpm run check-types, pnpm run knip.
