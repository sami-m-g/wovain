App map · updated Oct 22, 2026 for Genkit and Nemotron (#2)

wovain app map

wovain is a hosted MCP server for print-on-demand sellers. Any agent that speaks MCP with OAuth, such as ChatGPT or Claude, connects to it remotely. Inside one chat it turns an idea into a live Fourthwall product, makes video ads for it, and builds one Meta Advantage+ sales campaign guarded by five automated rules.

The main pieces

Piece What it does Where
Playbooks Tell the agent the steps for each stage: design, ads, campaign. Sent as the server's MCP instructions, through the get_playbook({ step }) tool and as the MCP prompts design, ads and campaign. apps/server/src/playbooks/
MCP server Tools that do the math, image and video work, storage and the Meta rules call. Money numbers are computed here, never by the model. apps/server/src/server.ts, apps/server/src/tools/, apps/server/src/lib/
Model calls wovain's own model calls go through Genkit to NVIDIA Nemotron 3 Super on Nebius Token Factory. The first is judge_design, which checks a design brief against the print and listing rules before the widget shows it. Without NEBIUS_API_KEY the check is skipped. research_trends searches Tavily for this week's news in a niche and returns ranked tee ideas with their links (Nemotron ranks them when the key is set), and screen_trademark searches a phrase before publishing. Without TAVILY_API_KEY both are skipped. apps/server/src/lib/ai.ts, apps/server/src/lib/design-judge.ts, apps/server/src/tools/judge.ts, apps/server/src/lib/tavily.ts, apps/server/src/lib/trends.ts, apps/server/src/tools/research.ts
HTTP app One Hono app on Node, run by Firebase App Hosting. Serves /mcp, the OAuth metadata that names AuthKit (/.well-known/oauth-protected-resource) and the home page. apps/server/src/index.ts, src/app.ts, src/routes/mcp.ts
Sign-in WorkOS AuthKit registers agents (CIMD or DCR), hosts sign-in and consent, and issues tokens; the server checks each token and the email allowlist. apps/server/src/auth/
Storage Firestore (through firebase-admin) for settings, designs and ads; a private Cloud Storage bucket for artwork bytes. Rules deny every client; only the server reads and writes. apps/server/src/firebase.ts, apps/server/src/store.ts, apps/server/firestore.rules
Widgets The interactive widgets in the chat: Settings, Design, Ad, Campaign. Built to single HTML files that the server ships. apps/widgets/src/<widget>/
Shared rules Schemas, breakeven economics and rule thresholds used by both server and widgets. packages/shared/src/
Deploy and telemetry App Hosting builds the widgets with pnpm build and runs node apps/server/src/index.ts; GitLab CI uploads the source with firebase deploy. Traces go to GitLab Observability when an OTLP endpoint is set. apphosting.yaml, infra/index.ts, .gitlab/ci/deploy.yml, apps/server/src/telemetry.ts
Connected services wovain connects to each merchant's own Fourthwall and fal as an MCP client (OAuth grants encrypted with Cloud KMS, apps/server/src/lib/upstream.ts, routes/connect.ts); Meta Ads stays connected in the agent, and wovain calls Meta's API only for rules. The agent's MCP connectors, apps/server/src/lib/meta-graph.ts

One action, end to end: “Add to campaign”

What happens between pressing Add to campaign on the ad widget and seeing the campaign widget with its rules.

  1. Ad widget button records the choice, then posts a chat message.
    apps/widgets/src/ad/ad-widget.tsx · onAdd → tool record_ad
  2. Request reaches /mcp with the merchant's OAuth token, which is checked before any tool runs.
    apps/server/src/app.ts → apps/server/src/routes/mcp.ts
  3. Ads playbook tells the agent that once no ad widgets are waiting, it starts the campaign step.
    apps/server/src/playbooks/ads.ts → apps/server/src/playbooks/campaign.ts
  4. Plan: budget in cents, ad names, product links with UTM tags.
    apps/server/src/tools/campaign.ts · campaign_plan
  5. Meta Ads connector builds the draft campaign, ad set and video ads.
    The agent's Meta Ads connector (outside this repo)
  6. Rules: five payloads in cents, posted to Meta's rules API.
    apps/server/src/tools/campaign.ts · create_rules → packages/shared/src/rules.ts · metaRules → apps/server/src/lib/meta-graph.ts
  7. Campaign widget shows Ready, Live or blocked, with each rule's threshold.
    apps/widgets/src/campaign/campaign-widget-view.tsx

Reference route: three stops

A reference route through the code above; it wasn't toured together.

1. The button · apps/widgets/src/ad/ad-widget.tsx, search onAdd

The widget calls the server tool record_ad directly so the choice is saved even if the chat moves on, then sends “Added the ads for design d1 to the campaign” so the agent continues with the playbook.

2. The rules tool · apps/server/src/tools/campaign.ts, search "create_rules"

Reads the added ads and each product's breakeven from the store, builds the five rules, skips any that already exist in Meta, and records which ones are in place. Without a Meta token it creates nothing and returns the fix instead.

3. The thresholds · packages/shared/src/rules.ts, search metaRules

Turns breakeven × your Settings multiples into Meta filters in cents: for example 3 × breakeven spend with no sales pauses an ad. The test apps/server/test/campaign-tools.test.ts pins the PRD demo tee's numbers ($30.96 kill, $8.26 scale).

To change this, start here

Default budget, rule multiples, video model packages/shared/src/settings.ts (also editable live on the Settings widget)

A widget's layout or copy apps/widgets/src/<widget>/*-widget-view.tsx; check it in Storybook first

A practice to reuse

Keep money math out of the model, and pin it with a test. The playbooks pass copy and choices; prices, breakeven and rule thresholds are computed by the server from stored data (packages/shared/src/ad.ts says so at the top), and campaign-tools.test.ts checks the exact cents Meta receives. When the first live run sent the rules to Meta, the thresholds matched without a fix. On any agent-built app that moves money, compute the numbers in code the model calls, and write one test with a worked example from the spec.

Run it again

  • pnpm install (Node 24, plus Java 21 for the emulators), then copy apps/server/.env.example to apps/server/.env and fill in the keys you need.
  • In ChatGPT (developer mode) or Claude, add https://app--wovain.us-central1.hosted.app/mcp as a remote MCP server, then sign in and approve access when AuthKit asks.
  • Locally: pnpm dev (starts the Firestore and Storage emulators and serves /mcp on localhost:3000) plus pnpm widgets:watch, and connect the agent to https://<tunnel>/mcp.
  • See every widget without an agent: pnpm storybook.
  • Checks: pnpm check, pnpm typecheck, pnpm test, pnpm test:integration, pnpm test:stories.

Paths and names can drift as the code changes.
